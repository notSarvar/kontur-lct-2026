# Сдача «Контура»: требования и оставшиеся работы

Проверка от 27.09.2026. Основание — предоставленный команде PDF «3. Билайн Бизнес», 9 физических страниц, SHA-256 `2cacb7da02445bf256a50a0c91995e95c6992f705e9252b40764b7865e8e306a`. Обложка считается первой страницей. Это проверка по имеющемуся PDF и текущему коду, а не подтверждение правил загрузки в личном кабинете организаторов.

## Нужен ли общедоступный сайт

**Публичный стенд по этому ТЗ необязателен.** В §3.2, физическая стр. 6, в строке «Запуск» написано:

> Локально; Docker — по желанию; публичный стенд приветствуется

В §7.2, физическая стр. 8, рабочий прототип определён как:

> Веб-интерфейс или учебное web-приложение, которое можно запустить по инструкции

Следовательно, для соответствия этому PDF достаточно воспроизводимого локального запуска. Свой домен, облачный сервер, Docker и отдельная база данных не являются условиями сдачи. JSON/CSV прямо разрешены в §3.2. Авторизация, промышленная отказоустойчивость и проверка на тысячах заявок также не требуются.

**Исходный код передать нужно.** §7.1 требует репозиторий при промежуточной сдаче; §7.2 — README, презентацию и исходный код при финальной. В PDF нет указания сделать репозиторий публичным. Практически проверяющим нужен доступ к переданному коду и инструкции; способ доступа следует сверить с формой сдачи.

§4 допускает live-демонстрацию или заранее подготовленную видеозапись. Рекомендуемая продолжительность — 5–7 минут. Запись полезна как запасной вариант, но не заменяет передачу исходников и рабочего прототипа.

**Что PDF не устанавливает:** адрес формы загрузки, её обязательные поля, дедлайн, допустимый размер файлов, правила приглашения экспертов в приватный репозиторий. Эти пункты нужно проверить в личном кабинете и сообщениях организаторов. Публичную страницу `https://i.moscow/lct` при этой проверке прочитать не удалось: HTTP 403. Нельзя считать отсутствие требования в PDF подтверждением отсутствия дополнительных правил платформы.

## Что осталось по технической части

1. **Закрыть расхождение навыков с PDF.** В §2.4.1 три навыка: локальные работы, подключение вместе с дозаказами, аварийные работы. Сейчас `server/domain/catalog.js` содержит четыре: подключение и дозаказ разделены по принятому ранее уточнению Q&A. Нужно зафиксировать согласованную трактовку; если ориентируемся буквально на PDF, объединить эти два навыка, сохранив разные типы и длительности работ. Затем обновить миграцию сохранённого дня/импорт, тесты и результаты сравнений. Менять это незаметно при публикации репозитория нельзя: изменятся допустимые назначения и потребность в инженерах.
2. **Зафиксировать небольшой приёмочный демонабор.** В §6 перечислены все три навыка, их комбинации у инженеров, четыре вида транспорта, пересекающиеся окна и конфликт, на котором последовательное назначение хуже. Три встроенных участка и генератор используют общественный транспорт; встроенные инженеры имеют по одному навыку. Модель поддерживает другие транспорты, но это нужно показать отдельным сохранённым JSON и воспроизводимым сценарием. Проверить несовместимый транспорт, отсутствие навыка, конец смены и срочное перепланирование. Оборудование — необязательное дополнение.
3. **Подготовить итоговое сравнение после фиксации справочника.** Сохранить вход, параметры, результаты baseline/ALNS, число назначенных и задействованных инженеров, километры каждого и всей команды. Процент экономии расстояния показывать только при одинаковом наборе выполненных заявок; иначе сравнивать покрытие и затраты отдельно. Текущие benchmark-файлы уже есть, но должны соответствовать окончательной версии модели.
4. **Подтвердить запуск по README в чистом окружении.** Проверить установку из lockfile, production-сборку, оба интерфейса, сохранение после перезапуска и сквозное демо; желательно повторить на ноутбуке второго участника. Для показа OR-Tools отдельно установить зависимости из `requirements-optimizer.txt`. Автоматические проверки в текущем окружении не заменяют проверку независимой установки.
5. **Подготовить финальные материалы.** Обновить презентацию под текущие экраны и результаты, приложить ссылку на код/архив и README. Отрепетировать сценарий на 5–7 минут и подготовить запасную видеозапись. Отчёт и один слайд от 17.09 — исторические материалы, а не подтверждение готовности финальной презентации.

Неопределённые адреса и предварительные офисы описаны в [ASSUMPTIONS.md](ASSUMPTIONS.md). Для показа нужно выбрать проверенный сценарий либо явно показать обработку отсутствующих координат; подставлять случайные точки нельзя. Оценочное время общественного транспорта допустимо по §3.2 при явном описании допущения: интеграция с платным транспортным API не является обязательной доработкой.

## Если команда всё же выберет публичный стенд

Это дополнительная работа: хостинг, HTTPS, адрес продукта и пульта, сохранение данных, проверка SSE и внешних ссылок. Сейчас пульт выбирается по отдельному `Host`; один бесплатный домен хостинга потребует адаптации адресации либо второго имени на тот же процесс. Два процесса с одним JSON-состоянием не заменяют эту настройку. См. [HACKATHON_WORKSPACE.md](HACKATHON_WORKSPACE.md).

Внешнее хранилище, например Supabase, понадобится при выборе хостинга без постоянного диска и требовании сохранять изменения между его перезапусками. Для локальной сдачи оно не нужно. В текущем прототипе нет разграничения пользователей; публикация обоих интерфейсов даст посетителям доступ к общему демонстрационному дню.
