# Отдельный адрес пульта хакатона

[Инструкция по кнопкам и сценарию показа](demo/README.md) · [Руководство диспетчера и инженера](system/README.md)

Публичный пульт: **http://158.160.161.151/hackathon**. SSH-туннель и настройка DNS для этой ссылки не нужны. Основной интерфейс находится на **http://158.160.161.151**.

Один Node-сервер обслуживает два интерфейса:

| Адрес по умолчанию              | Интерфейс                                                                                     |
| ------------------------------- | --------------------------------------------------------------------------------------------- |
| http://localhost:4317           | Продукт: диспетчер, инженеры, заявки, аналитика, поддержка                                    |
| http://localhost:4317/hackathon | Хакатон: сценарии, загрузка участков, симуляция времени, импорт/экспорт, сравнение алгоритмов |

Путь `/hackathon` (также с завершающим `/`) открывает пульт на любом адресе приложения. Локальный адрес `http://hackathon.localhost:4317` продолжает работать. Пульт открывается сразу на своей странице. В продукте нет вкладки «Демонстрация», включая мобильное меню. Из пульта кнопка «Открыть продукт» открывает рабочий интерфейс в новой вкладке.

## Общий день

Оба адреса используют один сервер, очередь команд, сохранённое состояние и SSE-синхронизацию. Изменение времени, заявок или сценария в пульте сразу видно диспетчеру. После действий, применения предпросмотра и перезагрузки пульт остаётся пультом. Выбор интерфейса не записывается в данные дня.

Симуляция выполняется, пока открыта вкладка пульта. Закрытие или перезагрузка вкладки останавливает её таймер; текущее время дня сохраняется на сервере.

## Локальный запуск

```sh
npm run dev
```

Откройте `http://localhost:4317` и `http://localhost:4317/hackathon`. При использовании отдельного локального имени: `hackathon.localhost` — локальное имя, доступное на этом компьютере, а не опубликованный сайт. Если браузер или системный резолвер не разрешает это имя, добавьте соответствие `127.0.0.1 hackathon.localhost` в локальные настройки DNS/hosts. В проверенной конфигурации Chromium правка hosts не требуется.

При `PORT=4330` оба адреса автоматически используют порт 4330. Для браузерных тестов задайте `TEST_URL=http://127.0.0.1:4330`; адрес пульта будет вычислен из этого порта. Для произвольного тестового домена можно передать `TEST_HACKATHON_URL`.

## Настройка публичных доменов

Публичный сервер уже обслуживает пульт по пути `/hackathon`. Дополнительно можно использовать отдельный домен. Пример для уже принадлежащего команде домена (замените имена `.example`):

```sh
npm run build
PRODUCT_ORIGIN=https://kontur.example HACKATHON_ORIGIN=https://hackathon.kontur.example npm start
```

Оба домена нужно направить через reverse proxy на **один** процесс приложения. Прокси должен сохранять исходный HTTP `Host`, обслуживать HTTPS и пропускать SSE `/api/events` без буферизации. При открытии `/hackathon` интерфейс выбирается в браузере по пути страницы; API использует тот же origin. На корневом пути отдельного домена интерфейс выбирается по точному соответствию `Host` адресу `HACKATHON_ORIGIN`; протокол и порт origin учитываются при настройке. Не запускайте два процесса с одним `DATA_DIR`: их состояния в памяти и очереди команд разойдутся.

API остаётся на каждом исходном домене: браузер обращается к относительным `/api/...`. Поэтому CORS не включается, прежняя проверка Origin для изменяющих запросов сохраняется. Это разделение интерфейсов; авторизации и изоляции пользователей оно не добавляет.

## Реализация и проверки

- `server/http/workspaces.js`: конфигурация адресов и выбор интерфейса по Host.
- `server/http/server.js`: сведения об интерфейсе в ответах с состоянием; единый backend и SSE.
- `src/app/App.jsx`: выбор пульта по пути `/hackathon` или отдельному Host.
- `src/features/scenarios/Hackathon.jsx`: страница демонстрации.
- `tests/browser/hackathon.spec.js`: публичный путь и отдельный origin, синхронизация, применение плана, перезагрузка, узкий экран и сохранённая проверка Origin.

Рабочий день на порту 4317 не используется для тестов; проверки запускаются с отдельным `DATA_DIR`.
