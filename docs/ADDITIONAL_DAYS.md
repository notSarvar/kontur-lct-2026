включает ID набора: отметки SOP, назначения и статусы не переносятся между днями.

## Путь загрузки

Пульт `/hackathon` → «Данные Билайн» → «Дополнительные дни» → нужный набор →
«Загрузить участок». Интерфейс читает единый серверный каталог `/api/datasets`.
Используется прежнее действие `dataset.load`: новый день, нормативы BK/HD,
синтетическая команда, география, оптимизация, назначение SOP и очередь согласования.
Как и раньше, явная загрузка заменяет текущий день и историю. Публикация новых файлов
сама по себе ничего не загружает в действующий день.

## Преобразование и допущения

- Узкий адаптер `normalizeAdditionalCsv` применяется только к зарегистрированным
  дополнительным наборам. Основной `normalizeOfficialCsv` и запрет контрольного
  распределения по бригадам остаются в силе.
- Адрес офиса берётся из исходного CSV соответствующего участка; координаты и
  существующие допущения о корпусе/строении наследуются из той же конфигурации.
- Все строки входят в новый расчёт, включая строки с исходными отметками
  «Выполнена» и «Отменена». Это независимое проигрывание исходного набора,
  не восстановление рабочего состояния на момент выгрузки. `Статус BK` сохраняется
  в `job.source.fields`, виден в исходных данных карточки и не становится статусом симуляции.
- Поле «Гигабитное подключение», если присутствует, сохраняется и отображается
  справочно. Новые нормативы длительности или квалификации из этого флага не выдумываются.
- Команда создаётся прежним методом по объёму работ и двум сменам; начальные точки
  всех инженеров совпадают с офисом своего участка.
- Неточные и не найденные адреса остаются на проверке. Координаты не подставляются
  по центру района или соседнему дому для искусственного увеличения покрытия.

Для набора из 102 заявок лимит рабочего дня и JSON-импорта поднят до 200.
Генератор нового дня по-прежнему создаёт 1–100 заявок; остальные проверки сохранены.

## Подготовка

`scripts/geocode.mjs` поддерживает `DATASET_IDS` для ограничения набора адресов.
Геокодирование кэшируется, идёт последовательно; передаются только адреса,
без номеров заявок и статусов. Повторное уточнение — `--refine`. Параметр `--preserve-cache <снимок.json>` защищает все записи исходного справочника от изменений при уточнении.
`scripts/prepare-walking.mjs` принимает тот же фильтр и сохраняет отдельную
матрицу для каждого ID. Использование матриц и оценочного режима не меняется.

Проверки: `tests/additional-days.test.js`, `tests/official-data.test.js`,
`tests/browser/additional-days.spec.js` и штатные проверки планирования.

## Результат геокодирования

После первичного запроса и уточнения получены координаты для 469 из 497 строк заявок.
28 строк остаются на проверке; они не исключаются из исходного набора.
В существующем справочнике сохранены без изменений все 198 записей.

| Югоцентр · день 2   |             75 |           2 |

Для всех шести наборов подготовлены отдельные пешие матрицы и геометрия пеших
участков в существующем формате. Три исходные матрицы и 39 прежних геометрий
сохранены без изменений. `scripts/check-additional-days.mjs` проверяет без сети
расчёт каждого нового плана в подготовленном режиме, соответствие офиса исходному
участку и учёт всех заявок (назначение либо явная причина неназначения).
Режим по умолчанию остаётся оценочным, как у исходных наборов; подготовленные
дорожные данные выбираются прежней настройкой расчёта.
